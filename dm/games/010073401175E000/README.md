# Crash Bandicoot 4: It's About Time (`010073401175E000`)

<!-- PEANUTS: a Peanuts Native profile and note (Banana Native has none for this title). -->

Update 1.2 (v131072). SDK 10.4.0. Toys for Bob, Unreal Engine 4.25 (project name `Lava`) with NVN graphics and Wwise sound. Modules `main`, `subsdk0` (NintendoSDK_movie) and `sdk`.

**Status (current): provisional profile, not run on a device from this profile yet.** The tools ran on the game's files on Linux: the survey, the shader split (50,618 shaders) and the rewrite of the three modules, with no `[RED]` line. The shader translation, the pack and a run on a phone are open. The same build was played on an AYN Thor Max (Adreno 740, Turnip) from an nx2android port, which uses the same host family, so the game is known to boot and play natively.

The rewriter's engine-wide rules all match this build, without a build ID:

- `dm/tools/ue_malloc.py`: FMallocBinned3's constructor at `main+0xf70c60`, called at `+0xf05718`; the name getter is slot 19, the layout of Unreal Engine 4.26 / 4.27, which 4.25 shares.
- `dm/tools/ue_region.py`: the engine region reserved at `main+0xf04ea4` in nninitStartup, its size stored from x8 at `+0xf04ea0`.
- `dm/tools/sdk_patches.py`: the function-matched cuts on this sdk build, the AddressRegionManager node area (1 GB to 62 MB, at `sdk+0x340d90`) and the 2 MB region alignment (`+0x340f84`).
- `dm/tools/ue_cvar.py`: `t.MaxFPS` at `main+0x7b0dea0`, `rhi.SyncInterval` at `+0x79c5030`, `r.Streaming.PoolSize` at `+0x7b0bd68`, `r.DynamicRes.FrameTimeBudget` at `+0x7ae3330`.

## Files and shaders

RomFS: 464 files, 9.29 GB, nearly all of it two paks, `Lava/Content/Paks/pakchunk0-Switch.pak` (3.2 GB, 54,043 files) and `pakchunk1-Switch.pak` (4.9 GB, 73,694 files). Both are pak version 9 (Unreal Engine 4.25) with a frozen index, Zlib in 64 KB blocks, not encrypted. `dm/gfx/tools/uepak.py` reads that version since this profile ([Pak version 9 and its frozen index](../../../docs/reference/shaders.md#pak-version-9-and-its-frozen-index)).

The shaders are in two shader code archives, both in `pakchunk0`, stored without pak compression:

| Archive | Shaders | Size |
|---|---|---|
| `Lava/Content/ShaderArchive-Global-GLSL_SWITCH.ushaderbytecode` | 1,461 | 7.4 MB (22.9 MB decoded) |
| `Lava/Content/ShaderArchive-Lava-GLSL_SWITCH.ushaderbytecode` | 49,986 | 313 MB (781 MB decoded) |

Every shader in them is an LZ4 block, which `uepak.py` decodes itself (`lz4_shaders`): no Oodle, so the phone needs no run of the game's own decoder. All 51,447 decode to LSLG records. The split keeps 50,618 after removing duplicates: 42,574 pixel, 7,350 vertex, 635 compute, 59 geometry.

`pakchunk1` holds cooked packages only. Its material shaders are the shared ones in the archives: a scan of all 73,694 files (13.5 GB decoded) finds the LSLG magic 8 times, each a chance match in texture or mesh data. `uepak.inline_paks` therefore does not scan it file by file.

## Frame rate

The game runs at 30 fps on the Switch with dynamic resolution. `fps_target 60` makes the host write three of the engine's console variables at every present (`dm/host/hle_fpslock.c`): `t.MaxFPS` 60, `rhi.SyncInterval` 1 and `r.DynamicRes.FrameTimeBudget` 16.17 ms (33.3 at a 30 cap). The budget is the frame time dynamic resolution sizes the picture for; left at 33.3 ms the engine would not lower the resolution for a frame that misses 16.7 ms. FPSLocker's entry for this build writes the same two values at the same addresses (`main+0x7b0deb0`, `+0x7ae3340`: each object's value pointer at +0x10). Unreal steps the game by the time that passed, so the speed stays right.

## Power

The Vulkan replay holds a floor under the GPU clock; on Turnip it goes through the kernel driver, and at its default (`DM_VK_GPU_FLOOR` 100) every frame's work runs at the highest clock, whatever the frame needs ([the floor's code and notes](../../gfx/vk_android/vka_dev.c)). The profile offers **Adaptive GPU clock** (Game settings > Game options, `DM_VK_GPU_FLOOR_AUTO`, live) and recommends it on for every phone (`recommend any`): the floor then rises in steps when a frame's span comes within 2 ms of the 16.7 ms period and falls when it stays 5 ms below it, so a frame with time to spare runs on the driver's own clock.

Not measured on this game yet: the clock, the temperature and the frame times with it on and off (open, below). If frames drop with it on, turn it off for this game; the Frame rate cap's 30 (the in-game panel) halves the GPU work instead.
